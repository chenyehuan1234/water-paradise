# 第三阶段接口与结算

## 坐标与数据

`src/world/types.ts` 定义纯逻辑数据。Y 是竖直轴，X/Z 是水平轴。方块 `(x,y,z)` 占据 `[y,y+1)`，其上表面为 `y+1`；角色位置是脚底高度。两格石柱占 `[y,y+2)`。桥板的 `y` 是承载面，玻璃的 `y` 是竖直面下缘。船的 `y` 是承载面：空船逻辑高度为 0，薄船板外观约 0.2 格；首块绑定方块占据 `[y,y+1)`，主角可站在 `y+1`。

| 数据 | 职责 |
| --- | --- |
| `LevelDataV2` | `version:2`、ID、名称、宽深、物件列表、水源、出生点、说明、可选验证路线 |
| `WorldObject` | ID、类型、X/Y/Z、朝向；船的 `cargo` 至多绑定第一块，后续上层物件仍在独立物件列表 |
| `ProjectData` | 章节及顺序、按 ID 索引的关卡、每关编辑设置、当前关卡、回收站 |
| `GameState` | 角色位置、朝向、当前物件、乘船 ID、回合、胜利状态 |
| `WaterCell` | 该列承接高度 `y`、顶棚 `ceiling`、压力水位 `head`、可见水位 `level`、深度与类型 |
| `WaterEdge` | 所属水层 ID、X/Y/Z、方向、起止水位、内部落水或虚空出口 |
| `ActionEvent` | 动作类型、物件 ID、起止位置，可选链条目标及出口方向 |

实体、边界和承载面分开存储。桥板不合并为空间体积，装饰不参与逻辑。固体的最高可占体素为 Y=31；可在上表面 Y=32 站立或设置标记。

## 水流求解

`solveWater(level, objects = level.objects): WaterSolution` 无副作用、无 Three.js 依赖。

1. 将固定实体与当前未装船的木块、箱子构成三维占格；忽略桥板、船、载荷、主角和装饰。
2. 每列实体之间的空隙成为独立区间。每个有承接面的空隙可以拥有自己的水层；底部无承接面的空隙只接收排水，不横向铺水。
3. 邻列空隙实际重叠的部分产生连接，玻璃面关闭对应高度的连接，连接保留最低可通水高度。开口玻璃不影响水路。
4. 边界和邻接无底虚空作为排水条件，用最小堆进行 minimax / Priority-Flood，得到各区间的最低溢流门槛。
5. 水源选择该列最高的承接面。从源区间仅沿可通过且水位不升高的连接展开，同水位连接完整展开。
6. 输出薄水、深水、内部瀑布及最终出水边。没有与源接通的区间输出干燥；不继承前一回合存水。

封顶区间可以保存高于顶棚的水头，但可见水位止于顶棚，不在屋顶实体内部生成自由水面。出口以「空隙层 + 水平格子边」标识；内部瀑布不计数，虚空瀑布固定显示四格。

水源的 X/Z 指定天空落水列；Y 用于编辑标记位置，不能让天空水穿透天花板。该模型为确定性离散稳定水位规则，不计算有限流量和惯性。

## 动作事务

`initialState(level)` 校验关卡、统一落稳和装载，再计算初始水流与浮船位置。初始化不产生驱船水花，也不消耗回合。

`applyAction(level, state, command): StepResult` 返回完整状态、水解、事件、是否接受和反馈文字。输入状态不修改。

- 命令为 `move(direction)`、`turn(direction)`、`pull`、`wait`。
- 原地转向不消耗回合；有效移动、拉取与等待消耗一回合。无效动作返回原状态。
- 动作先检查整组平移，携带上方动态物件；任何碰撞、两船交叉或角色无底坠落都拒绝整次动作。
- 推不动时才尝试攀爬一格。桥板只能同高进入，玻璃不能翻越，挡水石柱顶面不可供角色站立。
- 重力按从低到高的稳定顺序处理，落至第一个承载面。木块和箱子可以离场，角色必须有合法落脚点。
- 首块箱子或木块落入/平移进入空船面后永久变为一整格的 `cargo`；船与绑定块始终不挡水。后续箱子和木块保留 ID、重力和挡水性质，正常堆叠在绑定块上。
- 深水托起船，使船的承载面与水面齐平；干地和平流层搁底。浮动时通过支撑链带动普通上层物件和主角；整摞净空不足便停下，允许淹没。
- 上层普通物件移动会改变水路，因此水位、船位和支撑链反复结算到稳定状态；若出现循环，拒绝整次操作。
- 驱船水花只来自高于旧深水面的一次真实坠落。水位变化、持续瀑布、初始化和船移动不生成驱船事件。
- 水花按相邻同水位的船汇总向量，力量取落水前与水面的高度差。相反方向相消，两个轴的绝对值相同则不动；其余沿较强轴移动。玻璃阻隔水面时不传递驱船力量。
- 船滑行止于障碍或水层承接高度变化，不触发二次水花。多个受驱船按稳定 ID 顺序结算。
- 最后判断唯一出口及角色的水层，提交回合与胜利状态。

四种牵引关系均按一次事务预检：岸拉岸、船拉岸、岸拉船、两船相向各一格。乘坐关系沿支撑链判断；只有首块绑定的是箱子，船才可作为 X 的目标。X 指向上层独立箱子只拉该箱子及其普通上层物件，按实际层高检查，不牵动船。

`GameSession` 保留前后快照与动作路径（300 步）；撤销时反向播放路径，水从当前画面高度恢复，逻辑状态直接取历史快照。`StackingEditor` 的编辑历史独立（100 笔），试玩使用深拷贝。

## 编辑与渲染接口

- `StackingEditor.begin/paint/rectangle/end/cancel`：冻结起笔快照、整笔提交、避免重复取样位置。
- `resolvePlacement`：面邻接优先；玻璃默认在顶面自动吸附最近的边，已有玻璃的上沿叠高、侧缘延长；虚空命中放置层。`placementError`：拒绝覆盖占位。
- `validateV2` / `parseLevel` / `readJSON`：校验、V1 兼容读取和 JSON 限制；导入上限 20 MB。
- `ProjectStore.load/save/migrateLegacy/migrateOrigin4175`：IndexedDB 存储、旧版备份与跨端口迁移。旧页必须提供专用只读迁移页，否则提示 JSON 导入。
- `WorldView.show`：接受逻辑快照与事件，从当前显示位置接续。`animation: full | simple | system` 默认 `full`。相同指令序列不因动画开关改变状态。
- `WorldView.finish`：中止视觉动画，立刻定位到已提交状态。`dispose` 结束绘制与渲染器生命周期。

渲染使用实例化建筑、共享材质及几何体；完整包围的石块不绘制。此优化和剖视均不删除逻辑对象。水面按世界坐标连续绘制，同一连续水位不画内部泡沫缝。模型仅由代码生成。
