# V1 迁移、保存与恢复

## V1 → V2

旧关卡导入和首次发现旧浏览器草稿时自动迁移：

- 旧高度 `h` 的石柱转为 Y=0 到 Y=h 的 `h+1` 个固定石块；旧表面高度整体加一。
- 原有 X/Z 不变。出生点、水源、箱子、装饰都放在对应新表面上。
- 旧箱子转为 `crate`，保留 ID，获得第三阶段推拉与重力规则。
- 空格继续为虚空。迁移不会把上下层压成一个高度。
- 相对高差、水深、平流层分类和逐边出口数量保持一致；测试覆盖原四个示例以及涨水/隔离操作后的结果。

`levels/*.json` 中的第二阶段原件保留不动。迁移后的 12 关与完整章节工程位于 `levels/phase3/`。

## 浏览器存储

数据库名：`water-paradise-workshop`，版本 1。

| Object store | 内容 |
| --- | --- |
| `levels` | 按关卡 ID 存储 `{ id, level, settings }` |
| `meta` | 章节、排序、当前关卡、回收站 |
| `backups` | `v1-draft` 保存旧草稿完整原文 |

旧键 `water-paradise:editor:v1` 仍保留在 localStorage，不会删除。迁移成功保存 V2 后才写迁移备份标记，后续刷新不再重复导入。

## 4175 → 4180

新地址使用独立的浏览器存储。只有旧地址提供本工程的只读 `transfer.html` 时，4180 才自动读取旧章节、关卡、草稿与编辑设置。空库保留原 ID；已有内容时以新副本合并。迁移前把双方原文存入新库 `backups/from-4175`，验证新库保存和重读后才写 `meta/migrated-4175` 标记；旧地址的数据库始终不改动。旧船有多件 `cargo` 时，第一件继续绑定，其余按原 ID 和类型恢复为上层独立物件。

当前本机的 4175 服务来自另一个工程目录，没有该只读迁移页。本工程不会修改或关闭那个服务，4180 页面会明确提示自动迁移不可用。如果旧页支持 JSON 导出，可先在旧页导出整套章节，再在 4180 点「导入」；导入会先校验并作为副本加入。旧页数据继续留在原地址。浏览器不同配置文件之间也不能直接共享本地存储。

`scripts/verify-migration.mjs` 在隔离浏览器配置中模拟旧迁移页，验证空库迁移、已有内容合并、旧载荷转换、刷新恢复和旧库原样保留；这不代表当前被其他工程占用的 4175 已完成用户资料自动搬迁。

保存请求按顺序提交，章节与关卡同一事务更新。界面显示保存中/成功/失败。失败不清空内存，可继续导出当前关卡或整套工程。页面关闭前需确认保存状态；不同浏览器、不同地址/端口不共享 IndexedDB。

## 导入与删除

单关和整套工程均先完成校验再变更现有内容。无效数据不会部分写入。同 ID 或不同 ID 的导入都成为新的关卡副本，章节工程也作为新章节加入。

删除不会直接丢弃关卡数据，而是进入工程回收站；恢复保留原有 ID 与内容。单关恢复到原章节，原章节不存在时会创建恢复章节。整章可一并恢复。

试玩位置、箱子位置、永久载荷和胜利状态不会写回编辑稿。撤销/重做历史为本次打开期间的内存数据，不写入持久草稿。
